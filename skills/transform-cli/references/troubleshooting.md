# Troubleshooting

Relative paths in this file resolve to the skill directory, the folder above `references/`.

Run `unity transform doctor --json` first: it checks the SDK, its runtime, the libraries it needs, a session start, the license and the GPU, and each failed check names its fix. Then read the per-session log: `unity transform session logs --session <id> --all` (also after the session closed), or `~/.transform/logs/<id>.log`. It holds each CLI command (`[cli …]` lines) and each script's source next to what the SDK printed. The host's stdout, stderr and tracebacks go there and nowhere else. `run file` / `run code` also stream it to stderr while the script runs (not under `--json`).

When neither explains the failure and it looks like a bug in the CLI or the SDK rather than in the script, suggest the user report it with `unity bug --area transform` (Unity CLI 1.0.0-beta.15 or later). It sends their system information and logs to Unity, so don't run it without asking. Give the user the id of the session that failed (`data.sessionId`) to put in the description. Installed through the Unity CLI, the report carries the end of the 5 most recently written session logs, which may not include that one; with a standalone install, it carries none. Then suggest attaching the end of that session's log: save it with `unity transform session logs --session <id> --tail 5000` and pass the file to `--attachments`. Never suggest attaching `~/.transform/logs/<id>.log` itself: an attachment is sent whole and unredacted, and a log can run to hundreds of MB. The log holds each script's source and the file paths it used.

| Error text | Root cause | Resolution |
|---|---|---|
| `The host of session <id> exited before its bridge on port <port> came up.` (`SESSION_START_FAILED`, exit 1) | The host crashed while starting. The error ends with the log's tail. | Read the traceback, or `session logs --session <id> --all`, and fix what it names. A missing license or system library is reported as `NO_LICENSE` / `MISSING_LIBRARY` instead. |
| `The host of session <id> did not become ready on port <port>.` (`SESSION_START_FAILED`, exit 1) | The host stayed alive but didn't answer within 60 seconds (not configurable), so the CLI stopped it: usually a slow or unreachable floating license server, or antivirus scanning the SDK on first load. | Retry once. If it times out again with a floating license, run `unity transform license server status`; the log tail shows how far startup got. |
| `The Asset Transformer SDK could not load: <library> is missing` (`MISSING_LIBRARY`) | Linux only: `pxz.so` links system libraries this machine lacks. | Tell the user which packages the message names. `liblber-2.5.so.0` means Ubuntu 24.04, which lacks OpenLDAP 2.5, with SDK 2026.5 or earlier: install SDK 2026.6 or later (`unity transform sdk install`), which brings its own, or run in an `ubuntu:22.04` container. |
| `The Asset Transformer SDK needs the Microsoft Visual C++ Redistributable (x64)` | Windows only: the SDK's DLLs need the VC++ runtime. | Tell the user to run the `vc_redist.x64.exe` the message names, from the SDK's `bin\` folder; it needs administrator rights. |
| `Not an Asset Transformer SDK install (no pxz.pyd/pxz.so under ...)` (`SDK_INVALID`, exit 2) | The path has no `bin/pxz.pyd` (Windows) or `bin/pxz.so` (Linux/macOS). | Point at the SDK root or its `bin/` folder. |
| `This SDK has no Python runtime yet` (`NO_RUNTIME`, exit 4) | A release build found no runtime for this SDK: its setup failed, a registered build's `PixyzUI/requirements.txt` changed, or `~/.transform/runtimes` was deleted. | Run the `sdk install` command the message names, the same one `unity transform sdk status` prints beside each SDK whose runtime is `missing`. Nothing is downloaded twice. |
| `The SDK is registered, but setting up its Python runtime failed`, with a connection or download error | No network to Unity's Artifactory (`unity3ddist.jfrog.io`), or GitHub/PyPI for anything not mirrored there (`imgui-bundle` always comes from PyPI), often behind a proxy. | Set `HTTPS_PROXY` (and `PIP_INDEX_URL` for an internal PyPI mirror) in the shell's environment, not `~/.transform/.env`, which these aren't read from, then re-run the same `install`. The CLI's own downloads also honor `HTTP_PROXY`, `ALL_PROXY` and `NO_PROXY`. |
| The same error, naming a package with no build for this platform | The setup installs only prebuilt wheels, and that package has none here. | No fix: tell the user, with the package name, and suggest reporting it. |
| `CHECKSUM_MISMATCH` from `sdk install` | The download didn't match Artifactory's checksum and was deleted. | Retry once. If it fails again, a proxy between the machine and Artifactory is the usual cause: tell the user. |
| `A file in the runtime is past Windows' 260-character path limit` | Windows only: the home folder's path is so long that a package file under `~/.transform/runtimes` passes MAX_PATH, and long paths are off. | Tell the user to enable long paths (`LongPathsEnabled` = 1, as an administrator) or use a shorter home folder, then re-run the same `install`. |
| `Failed to spawn session host: 'uv' was not found on PATH` | A source checkout runs the host through uv. | Install uv, or use a release build. |
| `Could not open the UI for <id>; it is still running headless.` (`UI_ATTACH_FAILED`, exit 6) | The attach failed: a registered SDK without its `pxzui`, no display, no graphics driver, or an SDK folder the user can't write to (pxzui writes `callback_manager.py` there as it opens; a read-only SDK folder breaks only `ui open`, never a session's start). The session is fine. | Read `uiError` from `unity transform session info --session <id> --json` and keep working headless. Tell the user the fix it names: `session new --pxzui <folder>` for a UI elsewhere, a desktop session or X forwarding for no display, write access to the SDK folder. |
| `The only Vulkan device here renders on the CPU (...), and a window on one can crash the session, so none is opened.` | The machine has only a software Vulkan renderer (`llvmpipe`), as WSL does. The session is fine. | Keep working headless; screenshots still work, slowly. To look at the scene, use a machine with a GPU, or the Windows build from WSL. |
| `This machine has an integrated and a discrete GPU (...), and a window crashes the session unless Windows runs it on the discrete one, so none is opened.` | A Windows laptop with two GPUs, and the session's `python.exe` has a graphics preference other than High performance (`session new` sets High performance only where there is none). The session is fine. `doctor` warns with the same text in its `ui` check. | Keep working headless. For a window, tell the user to set that `python.exe` (the message names it) to High performance in Settings > System > Display > Graphics, then start a new session. |
| `The Asset Transformer SDK <version> for macOS has a bug that crashes the session as it builds a window, so none is opened.` | `ui open` or `session new --ui` on macOS with SDK 2026.6 or earlier, whose window crashes the session host. The session is fine and keeps its scene. `doctor` warns with the same text in its `ui` check. | Keep working headless: scripts, scene commands and screenshots work. Don't retry `ui open`. To look at the scene, tell the user to use a later macOS SDK release once one exists, or Windows or Linux. |
| The UI is a menu bar over a black viewport | pxzui saved a broken layout on an earlier teardown. | Run `ui close` then `ui open`: the host renames the broken layout (`.broken`) before attaching. If it persists, tell the user to close the UI and delete `%APPDATA%\PixyzSDK\PixyzUI_v<version>.ini` (Windows) or `~/PixyzSDK/PixyzUI_v<version>.ini` (macOS, Linux). |
| `This operation renders, and no OpenGL context could be created here` (`NO_GPU`) | No usable graphics driver. | Skip the screenshot and `algo remove-occluded`; everything else works, `algo decimate` included. On Linux, Mesa's software renderers (lavapipe from `mesa-vulkan-drivers`, and llvmpipe) let them render on the CPU, at 30 to 60 s a screenshot: suggest it to the user. Don't call `view` functions from `run code` / `run file` there: without a driver they can end the session, and only `scene screenshot` and `algo remove-occluded` check for one first. |
| `The import of <file> added no geometry, only empty occurrences …` (`COMMAND_FAILED`, exit 6) | `scene import --clear` (or `workflow run --input`) read nothing from the file: it is empty or damaged. The scene is left as it was. Without `--clear`, the same file imports as an empty occurrence, with a warning. | Check the file, or export it again from its source; don't retry it unchanged. |
| `The export also removed <n> line(s) (curves) from the session's scene …` (warning) | The SDK's `.pdf` / `.prc` writer deletes the lines it writes from the live scene, and no undo step brings them back. The file is fine. | Export every other format you need first, or re-open the model (`scene open` / `scene import --clear`) after a `.pdf` or `.prc` export. |
| `This SDK doesn't import '<ext>' files. 'scene formats --import' lists the formats it reads.` (`INVALID_COMMAND_ARGS`, exit 2) | The loaded SDK build reads no format with that extension. No flag changes what a build imports. | Run `scene formats --import --session <id> --json` and tell the user which formats this SDK reads. |
| None: a command succeeds and `scene info` counts don't change | Some algorithms report success and change nothing until the scene is prepared, such as `filletMesh` until lines of interest are marked (`identifySharpEdges` or `identifyLinesOfInterest`). | Read the call with `sdk api`, run the step it needs first, and compare the counts again. |
| `The Asset Transformer SDK keeps relaunching PiXYZFinishInstall` (`NO_LICENSE`) | Linux: a license file was copied into the SDK's license folder by hand, before the SDK's one-time setup step ran; the step then relaunches itself. | Tell the user to move the file out of the folder the message names, then run `unity transform license activate <path>`; it changes their machine, so ask first. With the file still in the folder, `license activate` refuses with `The license folder (…) already holds …` (`NO_LICENSE`); the remedy is the same. |
| `The Asset Transformer SDK can't start another instance on this machine` (`SDK_INSTANCE_LIMIT`, exit 7) | The machine already runs as many SDK instances as its license allows (sessions, or other programs using the SDK). The license itself is fine. | Close a session you started and no longer need (`unity transform session list`, then `session close --session <id>`) and retry. If none is yours, tell the user; don't close other jobs' sessions, and don't run `license activate`. |
| `The SDK's license installers left … taken in /dev/shm (…)` (warning, or the end of a `license activate` error) | Linux: the SDK counts its slot files in `/dev/shm`, not running instances, and `license activate` kept slots its installers left because it couldn't prove no process holds them. Until they go, sessions can fail with `SDK_INSTANCE_LIMIT`. | Tell the user: once no session (`unity transform session list`) and no other program using the SDK runs, the `rm -f` command the message names frees them. It needs root, so ask first; don't run it while other jobs' sessions run. |
| `The Asset Transformer SDK can't create its shared memory: Create shared memory failed` (`SDK_SHARED_MEMORY_LEFT`, exit 4), or on macOS the warning `The SDK's license installers left … taken in shared memory (…)` | Shared-memory objects of the SDK's names are left from an earlier process and the SDK can't open them: on macOS, root's, left by the license installers that `license activate` ran under `sudo`. The license itself may be fine. | Don't run `license activate`. Tell the user: once no session (`unity transform session list`) and no other program using the SDK runs, the command the message names removes them (it needs root, so ask first), or restarting the machine does. |
| `The Asset Transformer SDK has no license to run with` (`NO_LICENSE`) | The session checked its license as it started and found none, an expired one, one for another machine, or a license server that answered and refused (no free seat, a license file it can't write, no FlexLM on this platform). | Run `unity transform license status` and tell the user its `why not:` line and `valid:` dates. Both fixes change their machine, so ask first: usually `license server set <host:port>` for the organization's floating license server, else `license activate <path>` for a license file they received. |
| `The floating license server didn't answer` (`LICENSE_SERVER_UNREACHABLE`, exit 6) | The session couldn't connect to the license server set with `license server set`: a host name that doesn't resolve, a wrong port, a server that isn't running, or a firewall. The SDK's reason follows the text. A server that takes the connection but refuses (no free seat, a license file the SDK can't write, a platform without FlexLM) is `NO_LICENSE` with the SDK's reason instead, and so is a FlexLM server whose vendor daemon's port alone is blocked: only the port set is tried. | Tell the user the reason, and ask before any change: `license server set <host:port>` with the right address, or `license server unset` to go back to the license installed on the machine. |
| `The license file <path> still names the license server <host:port>` (warning from `license server unset`) | A session an earlier CLI started took a seat from the server, and the SDK replaced the machine's license file with one naming the server; that CLI kept no copy, so `unset` can't put it back. New sessions keep using the server. | Tell the user; the fix changes their machine, so ask first: `unity transform license activate <path>` with their license file. |
| `<step> needs elevation, which asks for approval, and prompts are forbidden here (UNITY_NON_INTERACTIVE)` (`COMMAND_FAILED`), or on macOS and Linux `<step> needs administrator rights, and sudo needs your password for them, which it can't ask for: <reason>` (`COMMAND_FAILED`, `data.reason` `noTerminal`, `json` or `promptsForbidden`) | `license activate` needs a UAC prompt (Windows) or `sudo` with a password (macOS, Linux), and can't ask: prompts are forbidden, or on macOS and Linux it ran under `--json` or with no terminal (often the case when you run it). | Tell the user to run `license activate <path>` themselves: from a terminal opened with Run as administrator on Windows, or in a terminal on macOS and Linux, after `sudo -v` there if prompts are forbidden or it runs with `--json` (in CI, as root or with passwordless `sudo`). It changes their machine. |
| `No session is running. Start one with 'unity transform session new'` (`NO_SESSION`) | Only `run file` / `run code` create a session. | Run `unity transform session new --name <job>` first, then pass `--session <job>`. |
| `Session <id> was started by an older CLI that would run the script without its arguments` (`SESSION_OUTDATED`) | `run file` / `run code` got arguments after `--`, and the session's host predates them. | Start a new session (`session new --name <job>`) and re-import the source, or pass `--isolated` for a one-shot script. |
| `Exception: SystemExit: <message> (exit code 2)` (`SCRIPT_FAILED`) | The script's `argparse` refused the arguments after `--`; the message is argparse's, and its usage line is in `data.output`. | Fix the arguments; `-- --help` prints the script's own usage. The session is fine. |
| `Exception: NameError: name '<word>' is not defined` or `SyntaxError` (`SCRIPT_FAILED`) from `run code` in Windows PowerShell, on a word that was in double quotes | Windows PowerShell drops every `"` from an argument it passes to a program, so the host ran different code. | Send the code on stdin instead: run `$OutputEncoding = [System.Text.UTF8Encoding]::new()`, so a character outside ASCII doesn't arrive as `?`, then pipe a PowerShell here-string (`@'` ... `'@`) to `unity transform run code - --session <id> --json`. Don't write a file for it. |
| `<n> sessions are named '<name>'` (`AMBIGUOUS_SESSION`) | Several running sessions carry that name (started by an older CLI, which allowed it). | Pass the id of yours from `data.candidates`. |
| `~/.transform/sessions.json can't be read` (`SESSION_REGISTRY_INVALID`, exit 1) | The file listing the running sessions is damaged. No command rewrites it, so no session is lost by mistake. | Tell the user: the file has to be fixed or moved aside by hand, and the hosts it listed stopped by hand. |
| `~/.transform/sdks.json can't be read` or `~/.transform/config.json can't be read` (`CONFIG_INVALID`, exit 1) | The list of SDK names, or the settings (default SDK, license server, update check), is damaged, for example cut short. No command rewrites it, so nothing in it is lost by mistake. A file saved with a byte order mark is read. | Tell the user the file in `data.configFile` has to be fixed or moved aside by hand. Moved aside, register the SDKs again (`sdk install --path <dir> --name <name>`) and set the default (`sdk use`). |
| `No session with id or name '<id>'`, `Session <id> is no longer running: …`, or `TRANSFORM_SESSION names '<id>', which is not running` (`SESSION_NOT_FOUND`) | That session never ran here, or it stopped: the message says whether it was closed or its host exited, and names the log. | If its host exited, read `session logs --session <id> --all` for why. If you created it, create it again and re-import the source; otherwise tell the user. Don't switch to one of `data.candidates`, because they may belong to other jobs. |
| `option '--session <id>' argument missing` (`INVALID_COMMAND_ARGS`) | An option's value started with `--`, often an empty variable (`--session $S --json`). A value can't start with `--` unless written with `=`. | Pass the value; one that starts with `--` goes as `--name=--value`. |
| `'session close --all' asks before it changes anything, and can't ask here` (`INVALID_COMMAND_ARGS`) | It confirms only on a terminal, never under `--json`, without a terminal, or with `UNITY_NON_INTERACTIVE`. | It closes other jobs' sessions too. Close only the sessions you opened, by `--session <id>`; use `--all --dry-run` to list them, and `--all --yes` only when the user asks for every session closed. |
| `Using session <id>.` on stderr | The command used the active session because none was named. | Pass `--session <id>` to choose; `session use <id>` changes the default. |
| `session list` shows `busy` with no command | The host is alive but didn't answer `info` within 1.5 s: a long SDK call, or a window being opened. Treat it as busy, not dead. | Run `session list` again; if it stays that way, read `unity transform session logs --session <id> --follow`. |
| `session list` shows `busy: <group> <command> <time>` | That command has not returned; `ping` and `info` still answer. It is not proof of progress: a hung script stays `busy`. A command sent meanwhile queues; one that times out (`BRIDGE_TIMEOUT`) or whose CLI is stopped never runs. | Watch `unity transform session logs --session <id> --follow`. Don't close it unless you started it; if you did and it has clearly hung, run `session close --session <id>`: without `--force` it stops a host still busy after about 5 seconds, discarding the scene, which can't be exported first. Then start over. |
| `… answered with something that isn't valid JSON …; the command ran nonetheless` (`INTERNAL_ERROR`, exit 1) | The session's host sent an answer the CLI can't read. The command did run, so the scene may have changed. | Check the result with `scene info` or `occurrence info` before retrying; don't repeat a command that changes the scene blindly. Report it with `session logs --session <id> --all`. |
| `session list` shows `unreachable` | The CLI can't connect to the host at all. | Read `session logs --session <id> --all`. If you started it, `session close --session <id>` stops it even though it doesn't answer; it never stops a process it can't confirm is the host (one that took its PID after a crash or restart). |
| `session close` warns `Process <pid> in <id>'s entry is still running, but it can't be confirmed as the session's host …` | An older CLI started the session, so nothing records when its host started, and it doesn't answer. The session is dropped from the list and the process left running. | If that PID is a Python process running `session_host.py`, stop it by hand; tell the user rather than kill a process you didn't start. |
| A session vanished from `session list` | Its host died; the registry drops dead pids on every read. | Read that session's log for why, then recreate it. |

## Removed spellings

Older builds took these spellings, and examples you've seen may still use them. This build refuses each with `INVALID_COMMAND_ARGS` (exit 2), except `--session .`, which fails with `SESSION_NOT_FOUND` (exit 6) because `.` is read as a session's name. Use the spelling on the right.

| Removed | Use instead |
|---|---|
| `run info`, `run import`, `run tessellate` and the other `run <verb>` commands | The `scene`, `algo` and `material` commands |
| `sdk help` | `sdk guide` |
| `algo optimize` | `workflow run optimize`, or `algo decimate` then `algo remove-occluded` with values for the model at hand |
| `sdk install <name> --path <dir>` | `sdk install --path <dir> --name <name>` |
| `sdk install --into <dir>` | `sdk install --output-dir <dir>` |
| `--session .` | `--isolated` |
| A session id without `--session` | `--session <id>` |
| `session ui-open`, `session ui-close` | `ui open`, `ui close` |
| `viewer open`, `viewer close`, `session new --viewer` | `ui open`, `ui close`, `session new --ui` |
