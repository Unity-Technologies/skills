# Pitfalls — mistakes that survive compilation

Read this before handing off, and whenever telemetry data is missing or doubled.

| Symptom | Cause | Fix |
|---|---|---|
| A context's data is missing; only a warning in the log | Mismatched Exit dropped at runtime (strict LIFO stack) | Exit innermost-first; never `ExitSession` while other contexts are open |
| `Apply()` warns; a collector is missing early events | Collector added in a later `Configure()` pass | All collectors in the bootstrap chain; later passes change context only |
| Consent event sent but data still flows (or stays gated) | `SendConsentChange` alone changes nothing | `EndUserConsent.SetConsentState(...)` → `SendConsentChange` → `gate.Open()`/`gate.Close()`, in that order |
| New code does not compile in an asmdef project | Missing assembly reference | Add `Unity.Insights.Events` to the asmdef's `references`, and `Unity.Insights.Events.Generated` once any `.ugtsevent` schema exists |
| The ingest collector was put behind the consent gate | Consent was read as send/don't-send; on the telemetry stream it is a stamp: events always send with the intent statuses on each record, and consent governs identifier use downstream. The package's `EventsCore.Configure()` doc example gates `GameTelemetry`; that example predates the parallel-consent rule, do not copy it | Ungate the ingest collector; gate only developer-owned destinations (placement-rules Consent) |
| Your model's screen count equals the scene count | The scene list was used as the screen model | Classify from C# state owners; cite the transition site as evidence |
| Instrumentation lands in the wrong places on a large project | In-context survey model did not survive context churn | Write `telemetry_game_model.json` with `file:line` evidence before wiring |
| State lost between pipeline calls | Domain reload wipes C# statics | Never stage state in statics; persist or recompute |
| Second build invocation kills the Editor | The pipeline blocks during a build; a re-invoke collides | Poll the build artifact; never re-invoke |
| A long pipeline command times out | Per-call execution limit | Chunk long work into smaller calls |
| Pipeline unreachable right after entering or leaving play mode | The pipeline server drops for a few seconds around play-mode transitions | Retry with backoff; do not fail the step |
| Pipeline dead, project loads | Safe Mode (compile errors) disables the pipeline | Fix compile errors first; `unity pipeline list` distinguishes Safe Mode from no Editor |
| Modal dialog hangs every pipeline call | A save prompt or dialog is open in the Editor | Avoid triggering save prompts; prefer headless commands |
| Crash on app termination with a native sheet up | Platform teardown dismisses the VC after the scripting VM died; the lifecycle callback re-enters a dead VM | Both teardown guards in the native-shell reference: `Application.quitting` uninstall AND the native will-terminate observer |
| Two screen enters seconds apart for a native surface | The engine wrapper that presents the sheet already writes the id | Writer census before wiring; suppress the engine writer on the native path |
| Enter/Exit fire on device rotation (Android) | Config-change recreation runs the lifecycle edges | The pid-tokened saved flag plus `isFinishing() && !isChangingConfigurations()` guard |
| Purchases double-counted from a native paywall | A native `record("purchase_initiate", ...)` beside the C# IAP callback wiring | The funnel stays on the IAP callback seam; the native side adds the screen only |
| Device test builds (TestFlight, internal APK) polluting production metrics | On package versions without `WithSandbox`, `sandbox` is runtime-set from `Application.isEditor` and a device test build is production-shaped | Check `EventsBuilder` for `WithSandbox(bool)` and set it on test builds; where absent, disclose it and separate test devices server-side by build identity |
| A run's economy unusable for balancing | One aggregate event at run end instead of per-transaction events | One `SendResourceEarn`/`SendResourceSpend` per balance change, at the chokepoint |
| Custom events absent from production while typed and context events land | The manifest was uploaded but the `.ugtsevent` schemas were never published; ingest drops a custom event whose name and pinned version are not PUBLISHED in the Schema Registry | Deploy every `.ugtsevent` the manifest pins (the registry reference, deploy step 3) and confirm *Deployed* or *Up to date* at the pinned version |
| Session exits missing for force-killed sessions, or every quit logs "Exit 'Session' called but the innermost open context is '<none>'" | A kill runs no quit handler; the package reconciles the frames it checkpointed on the next launch (every target but WebGL). The warning on every quit is a second teardown handler running after the package's own | Expect the kill's exits one launch late as `Abandoned` / `sys_reconciled` and say so in the report; write no teardown handler of your own except under `#if UNITY_WEBGL && !UNITY_EDITOR` (placement-rules Teardown) |
| Failed attempt exits carry no cause, or causes the registry never declared | `ExitAttempt(Outcome.Failed)` without `outcomeReason`, or reasons improvised at the call site | Declare the reasons enum in the registry and carry the cause on every failed exit (placement-rules Outcomes) |
| `Ga4PurchaseMode.Unspecified` throws at `Apply()`, or a checkout funnel shows in GA4 with no purchases behind it | The mode was passed as `Ga4PurchaseMode.Unspecified` (the parameter has no default), or the commerce family was switched on without the developer's explicit ask | Ruling 9's default posture: `SuppressAutoCollected` plus all 11 commerce names in `dropEvents`; unlock only on the explicit ask, per the version gate (the rulings reference, ruling 9) |
| The Log collector prints nothing and the console warns that Engine Diagnostics is not enabled | The engine's Insights module is not running, so `Apply()` registered no collector: an editor before 6000.2.7f1, a target the engine builds no module for (WebGL, Linux), a stripped module, or batchmode and the test runner; on 6000.2.7f1 to 6000.4.x also the project's Engine Diagnostics setting being off (Edit > Project Settings > Services > Diagnostics), which from 6000.5.0a9 no longer drives the gate | Name which it was (the warning quotes the gate's reason) and what to change, verify on a supported editor and target (Windows, macOS, iOS, Android), and say in the report that nothing was delivered where the gate was shut; never let instrumentation silently no-op |
| The Log collector prints nothing, with "Deferred buffer for ServicesCoreReadySignal is full" or "Collection mode is Off" in the console | Every collector holds its deliveries until Unity Services Core is initialized (256, then dropped), and the game never called `UnityServices.InitializeAsync()`; or the project's remote collection policy is Off, which it is for a project with no cloud project id or a service that never answers | When the game has no Core initializer, kick off `UnityServices.InitializeAsync()` at bootstrap; when it has one, make sure it runs and never add a second ahead of it (placement-rules Bootstrap); link the project and verify from an Editor that can reach the service; say in the report that nothing was sent for that launch |
| `Collectors.GoogleAnalytics` does not compile | The Firebase Analytics package is absent, so `GOOGLE_ANALYTICS_AVAILABLE` is not defined (or the target is WebGL), and the `Add(...)` line sits outside the guard | Write the `Add(Collectors.GoogleAnalytics(...))` line inside `#if GOOGLE_ANALYTICS_AVAILABLE && !UNITY_WEBGL` (the `Ga4PurchaseMode` enum compiles on every target); when the SDK is absent, carry it as its own plan line, "adds dependency: Firebase Analytics SDK (`com.google.firebase.analytics`) plus the developer's `google-services.json` / `GoogleService-Info.plist`", which only the developer can supply; never add the define by hand |
| Purchase events vanish from every chain collector (the sandbox capture still lists them) with a one-time warning naming the IAP+ SDK | `com.unity.purchasing` 5.4 or later is installed, so the package leaves the purchase funnel to it | Expected: wire only `SendPurchaseCancelled` and the non-funnel store events; say in the report which SDK owns the funnel and that GA4 commerce stays at ruling 9's posture |
| A custom event cannot be sent; `SendCustomEvent` is inaccessible | The stringly sender is internal; custom events are schema files | Create the `.ugtsevent` schema and call the typed `Events.SendX...` the Editor generates; reference `Unity.Insights.Events.Generated` from game asmdefs |
| Firebase never configures on the device (`InvalidOperationException` from the game's `CheckAndFixDependenciesAsync`), or GA4 alone receives nothing all session with a "Deferred buffer for GoogleAnalyticsCollector is full" warning (the warning names the inner type; a `ServicesCoreReadySignal` one is the row above) | Two dependency checks in flight: the GA collector starts one at `Apply()`, and the game's own Firebase init starts another; the SDK throws for the second. The collector retries its own for up to 30 s, then reports itself unavailable | One check at a time, chain first: the game's check starts after `Apply()` returns and retries on that exception with a short delay (placement-rules Bootstrap); on a retrofit the change to the game's init is gated, and the GA collector stays out of the chain until it is applied |
| After instrumenting, UGS services (Remote Config, Cloud Save, ...) run against the default environment instead of the one the game selects | A bare `UnityServices.InitializeAsync()` added at `BeforeSceneLoad` ran before the game's own initializer; Core keeps the first call's options, so the game's later `SetEnvironmentName(...)` is ignored | Remove the added call and keep the game's initializer as the only one (placement-rules Bootstrap) |
| The ingest collector is behind a gate driven by a remote flag | A kill switch, not consent; allowed | Not a finding by itself. Check that the gate resolves on every boot path (a timeout fallback when the flag source never answers, knowing `Close()` is final for the session), that its buffer capacity is named, and that the flag's value never derives from consent, locally or on the server (Decisions, the kill-switch row) |
| Typed senders do not compile on a clean checkout or in a headless build | `Assets/InsightsEvents/Generated/` not committed, or stale after a schema change; the automatic regeneration runs on `EditorApplication.delayCall`, which a batch open does not reach | Commit the generated folder with its asmdef and `.meta` files; when a schema changed, regenerate in the Editor and commit, or run the `Services/Insights/Regenerate Custom Events` menu item from a project editor method in its own batch invocation before the build (api-surface Custom events) |
| No record carries a `releaseId` | The package stamps it only when a Live Release is active (Authentication signed in to a release) and Services Core is initialized; unset envelope fields are omitted from the wire record | Expected when no release is active: the manifest's `schema_version` and `registry_hash` are the registry identity on the envelope; report it (the registry reference, Runtime registry identification) |
| Production play lands on the staging gateway | A staging endpoint passed to `Collectors.GameTelemetry(...)` and left in the release build | The default endpoint is production; pass one only when the developer names it, and name it in the report (api-surface Envelope calls) |
