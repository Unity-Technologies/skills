# Link the Project to Unity Cloud

UGS calls need a linked Unity Cloud project ID. Linking writes `ProjectSettings/ProjectSettings.asset`: do it only when the task needs service calls or asks to link, after the restore point. Pass `--project-path <path>` to every `unity command` below, because without it the CLI drives the Editor of the shell's current folder, which may be another project.

1. A non-empty `cloudProjectId` in `ProjectSettings/ProjectSettings.asset` means it is linked: skip the rest.
2. Ask the user before linking. Run `unity auth status`; if it reports signed out, run `unity auth login` and ask the user to finish signing in in the browser it opens, because linking needs a signed-in account.
3. Without `--cloud-project`, the CLI reuses `UNITY_CLOUD_PROJECT`, then the saved default (`defaultCloudProjectId` from `unity cloud project current --format json`), and creates a project only when both are empty. To reuse one, pass `--cloud-project <id>`. If either is set and the user wants a new one, ask first, then clear the saved default with `unity cloud project clear-default` and remove `UNITY_CLOUD_PROJECT` from the link command's own environment in step 6 (for example `env -u UNITY_CLOUD_PROJECT unity projects link cloud ...`), because your shell inherited it and the user unsetting it in theirs doesn't change yours. Recheck both are empty before step 6 creates the project.
4. Check `Packages/manifest.json` for `com.unity.pipeline`: closing gracefully, `--until-ready` and `script eval` need it. If it is missing, add it with `unity pipeline install --project-path <path>` (Unity 6.0+), say so in the report, and run `unity status --until-ready --project-path <path>` before closing, because an open Editor loads Pipeline only after it refreshes: on `STATUS_PIPELINE_LOAD_PENDING`, ask the user to focus the Editor and check again. If it can't be added or doesn't load, ask the user to save and close the Editor themselves, and in step 7 check only the asset.
5. `unity close <path>` exits without saving, so ask the user to save their work first, then run it: an open Editor keeps the old link and can save it back over the new one.
6. Run `unity projects link cloud <path> --format json`, plus `--cloud-project <id>` when reusing. When it will create a project, first ask whether the game is directed at children under 13 and add `--coppa compliant` if so: the default is `not_compliant`. Never pass `--coppa` with `--cloud-project` (error `COPPA_ARGS_CONFLICT`); change an existing project's COPPA setting in the Unity Cloud dashboard.
7. Verify: if `data.editor.restartRequired` is `true`, an Editor still had the project open: close it, then check the asset still holds the new ID, and if not rerun with `--cloud-project <id>`. Reopen with `unity open <path> --until-ready --format json` (a plain `unity open` returns before the Editor can answer commands) and check `cloudProjectId` in the asset and `CloudProjectSettings.projectId` (via `unity command script eval --project-path <path>`) equal `data.cloudProject`'s ID. Without Pipeline, `--until-ready` times out, so reopen with plain `unity open <path>`, check only the asset's ID, and report that the Editor-side check was not run. On failure, stop and report the error code.
8. Never hand-edit the asset or write an Editor-side linker: a manual edit can mismatch project and organization IDs.
