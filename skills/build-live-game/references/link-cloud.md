# Link the Project to Unity Cloud

UGS calls need a linked Unity Cloud project ID. Linking writes `ProjectSettings/ProjectSettings.asset`: do it only when the task needs service calls or asks to link, after the restore point. Pass `--project-path <path>` to every `unity command` below, because without it the CLI drives the Editor of the shell's current folder, which may be another project.

1. A non-empty `cloudProjectId` in `ProjectSettings/ProjectSettings.asset` means it is linked: skip the rest.
2. Without `--cloud-project`, the CLI reuses `UNITY_CLOUD_PROJECT`, then the saved default (`defaultCloudProjectId` from `unity cloud project current --format json`), and creates a project only when both are empty. To reuse one, pass `--cloud-project <id>`. If either is set and the user wants a new one, ask first: `unity cloud project clear-default` clears only the saved default, and the user must unset `UNITY_CLOUD_PROJECT` in their own shell.
3. Check `Packages/manifest.json` for `com.unity.pipeline`: closing gracefully, `--until-ready` and `script eval` need it. If it is missing, add it with `unity pipeline install --project-path <path>` (Unity 6.0+) and say so in the report. If it can't be added, ask the user to save and close the Editor themselves, and in step 5 check only the asset.
4. `unity close <path>` exits without saving, so ask the user to save their work first, then run it: an open Editor keeps the old link and can save it back over the new one.
5. Run `unity projects link cloud <path> --format json`, plus `--cloud-project <id>` when reusing. When it will create a project, first ask whether the game is directed at children under 13 and add `--coppa compliant` if so: the default is `not_compliant`. Never pass `--coppa` with `--cloud-project` (error `COPPA_ARGS_CONFLICT`); change an existing project's COPPA setting in the Unity Cloud dashboard.
6. Verify: if `data.editor.restartRequired` is `true`, an Editor still had the project open: close it, then check the asset still holds the new ID, and if not rerun with `--cloud-project <id>`. Reopen with `unity open <path> --until-ready --format json` (a plain `unity open` returns before the Editor can answer commands) and check `cloudProjectId` in the asset and `CloudProjectSettings.projectId` (via `unity command script eval --project-path <path>`) equal `data.cloudProject`'s ID. On failure, stop and report the error code.
7. Never hand-edit the asset or write an Editor-side linker: a manual edit can mismatch project and organization IDs.
